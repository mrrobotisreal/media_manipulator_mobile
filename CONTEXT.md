# Media Manipulator mobile app: context

Expo / React Native client (Android first, iOS later) for the Media Manipulator API. Planning, tickets, ADRs and design docs live in `../docs/mobile-app/` (roadmap, `design/ARCHITECTURE.md`, `adr/MA-0001`..`MA-0009`).

## Vocabulary

- **App**: this repo's Expo application. Store name "Media Manipulator"; launcher label `MediaManip` (`MediaManip Dev` / `MediaManip Preview` for the other variants).
- **Variant**: `development | preview | production`, selected by `APP_VARIANT` in `app.config.ts`. Each has its own ids, scheme and EAS profile, so all three install side by side.
- **Tool**: one media operation (e.g. compress video) exposed by the API; grouped into **Families** (video, audio, image, caption, document).
- **Job**: one server-side run of a Tool on an upload; has status, progress and a **Result** (downloadable output).
- **Quota metric**: what the API meters, `ops` or `ai_ops`. **Tier**: the account plan reported in `X-MM-Tier`.
- **Sync gate**: after Firebase sign-in the app calls `POST /api/account/sync`; `(app)` routes render only when `auth.status === 'ready'`.
- **Visitor id**: per-install UUIDv4 (persisted). **Session id**: UUIDv4 that rotates after 30 minutes without activity (background or idle); `ensureFreshSession()` in `src/analytics/session.ts` is the only rotation point, called on every `track`, every `buildHeaders()` and on foreground, so analytics `session_id` and `X-MM-Session-ID` are always the same value (MA07). Sign-out also rotates it.
- `Darkroom Instrument` is only the name of the design-token system (`src/ui/tokens.ts`), ported from the web; it is never shown. (The old rule "the word Darkroom never appears in the app UI" is withdrawn by ADR MA-0012: the video editor is called **Darkroom**.) Since MA58 **Darkroom** and **Motion** (the SVG animator, code name `vector`) both appear in the app UI: History's Projects segment lists their projects.
- **MmError**: the one error shape from `src/api/errors.ts` (`{status, code, message?, details}`); every API failure is normalised to it. Screens switch on **error code** (`MmErrorCode`: client codes like `network`, `rate_limited`, `contract_mismatch`, the API's snake_case codes, or `api:<code>` for ones this build does not know), never on English text.
- **Quota observation**: on every 2xx the baseQuery reads `X-MM-Tier` / `X-MM-Quota-*` and dispatches `quota/observed`; on other failures it invalidates the `Account` tag instead.
- **Token provider**: `setIdTokenProvider(fn)` in `src/api/authToken.ts`; MA04 registers Firebase's `getIdToken`. `buildHeaders()` (in `baseQuery.ts`) is the only place request headers are built, including for uploads, SSE and downloads.

- **Web shard**: a JSON file copied by `scripts/sync-web-i18n.mjs` from the web's `i18n/locales/<code>/` into `src/i18n/generated/`; namespaces `interface`, `error`, `accessibility`. Read-only here; translator-workbench edits arrive on the next sync.
- **App shard**: `locales/<code>/app.json`, namespace `app` (default); app-only strings, keys grouped by screen, present in all 18 locales.
- **Catalog mirror** (MA07): `src/analytics/events.ts` (`EVENTS`, `EVENT_PRIORITY`, `EventPropsMap`), the app's copy of the analytics service's `internal/catalog/catalog.go`, checked from that repo by `TestAppEventsParity`. Names only as `EVENTS.X` (lint rule + `events.test.ts`); a new name lands in the analytics catalog's `appRolloutBatches` and is deployed first.
- **Outbox** (MA07): `src/analytics/outbox.ts`, the MMKV-persisted event queue on its own instance `mm-analytics` (1000 events / 1 MB, oldest dropped; events older than 7 days dropped at flush). Flushed p0 at once, p1 after 2 s, otherwise every 15 s or at 20 events, and on background / reconnect; one flush in flight.
- **Screen pattern** (MA07): the `screen_viewed.screen` (and `context.pathname`) value: the Expo Router segments with `(group)` segments and `index` dropped and dynamic segments kept as `[param]` (`/tool/[family]/[toolId]`); the Tools tab is `/tools`. Never a concrete id.
- **Mobile-dev key** (MA06/MA07): the `mmk_appdev_…` write key in the development and preview EAS environments (`EXPO_PUBLIC_ANALYTICS_WRITE_KEY`); the analytics service marks every event `is_self`, so test traffic shows in the admin events browser but never in aggregates. Production builds carry the `mmk_app_…` mobile key. An empty key disables analytics in that build.
- **Opt-out** (MA07): `settings.analyticsOptOut`, the "Share usage analytics" toggle (Account tab until MA22's Privacy screen). On: no capture, the outbox is cleared, timers stop; off again: capture resumes with the same visitor id. Past data is deleted only by MA22's "Delete my analytics data".
- **client_error** (MA07): one quality event per distinct error per session (max 10), from the root error boundary (`react`), the chained global JS handler (`window`), Hermes unhandled rejections (`promise`) and manual call sites (`contract_mismatch`, `no_absolute_url`). The message is scrubbed (query strings, tokens, emails, ids, digits) and cut to 200 chars; `stack_hash` is 16 hex of SHA-256 over message + first 5 frames. Stacks go to **Crashlytics** only (`src/analytics/crashlytics.ts`; collection off in development builds).
- **Locale override**: `settings.locale` (null = follow the system); resolved by `resolveLocale` and applied by `setAppLocale`.
- **RTL reload**: switching to or from he-IL / ar-SA flips layout direction, which needs a confirm sheet, `I18nManager.forceRTL` and `Updates.reloadAsync()`; same-direction switches are live.
- **Sync gate** (MA04): `src/auth/syncGate.ts` follows Firebase auth state: `unknown -> signedOut | syncing -> ready | syncFailed`. Sync retries 1 s, 3 s, 9 s; a 401 fails immediately. `signupSource` is the method just used, else the first `providerData` entry (`methods.ts`).
- **Linking**: on `auth/account-exists-with-different-credential` the pending credential is held in memory in `src/auth/linking.ts`; after the user signs in with the other method it is linked. Android Apple (web flow) has no credential, so a "Link Apple" offer appears instead.
- **Re-auth**: `reauthenticate({kind})` in `src/auth/reauth.ts` returns a fresh ID token (`auth_time` < 5 min) for account deletion (MA22).
- **Session expired**: MA03's `auth/sessionExpired` action; `src/auth/gate.ts` signs the user out and the sign-in screen shows a notice.
- **Firebase boundary**: only `src/auth/*` imports `@react-native-firebase/auth` and google-signin (lint-enforced); the jest manual mocks live in `__mocks__/`.
- **Tool row** (MA10): one `ToolDefinition` in `src/tools/registry.ts` (38 in v1), built in `src/tools/families/{image,video,audio,ai,metadata}.ts`. A **family** is one of those five groups (Tools tab sections, route segment `tool/<family>/<toolId>`).
- **Preset** (MA10 type only): a named `Partial<defaults>` variant of a tool for a folded web page, with its own analytics slug.
- **Analytics slug**: the web tool slug a row reports as `context.tool_slug` (first folded slug, never an alias in the web's `TOOL_ALIAS_OF`); keeps web and app funnels comparable.
- **Endpoint `auto`**: presign for a video file, multipart upload otherwise (`resolveTransport`).
- **Intake** (MA11): getting a user file into the app as an `IntakeFile`: a stable `file://` copy under `cache/intake/<id>/` (never a `content://` URI), made by `src/files/intake.ts` before any check that needs the bytes. A 24 h sweep (start + foreground) deletes unreferenced copies.
- **Share-into** (MA11): Android `ACTION_SEND` / `SEND_MULTIPLE` via `expo-share-intent` 8.x. The plugin receives `*/*` and `src/files/share-intent.ts` filters by MIME in JS; a share is held in memory until `auth.status === 'ready'`, then routed to `app/(app)/intake.tsx`. iOS share extension is MA36.
- **Pre-flight check** (MA11): pure `src/files/preflight.ts` run before any upload: `unsupported_type`, `too_large`, `too_long`, `empty`, `too_many`, against the cached `/account/me` limits. Skipped (never guessed) while the snapshot loads; a failed duration probe never blocks.
- **Job record** (MA12): one `JobRecord` in the persisted `jobs` slice (`src/jobs/types.ts`), keyed by **local job id**; carries the lifecycle `state`, upload/server progress, the last server snapshot and the built options (so Try again re-sends the same job). The newest 50 persist.
- **Local job id** (MA12): `local_<uuid>`, created by `startJobs()` before the server assigns `jobId`; `findJob` accepts either id (the job route and push deep links).
- **Job state** (MA12): `queued -> uploading -> (finalizing) -> pending | processing -> completed | failed`; side exits `rejected` (API refused the upload; MA16 renders it), `upload_failed` (retryable), `lost`, `cancelled`, `stopped`. Only `transition()` moves a record.
- **Lost job** (MA12): a persisted `pending`/`processing` job whose `GET /job/:id` is 404 (the API's job map is in memory). `lostReason` `server_restarted` (< 24 h since accepted) or `expired`.
- **Stop watching** (MA12): after acceptance there is no server cancel; the app drops tracking (`stopped`), the job still runs and counts. Before acceptance, Cancel aborts the upload (no job, no charge).
- **Result descriptor** (MA13): `describe()` in `src/results/describe.ts`, the pure answer to "what did this job produce?": kind from the result file extension first, then the registry row's `webTask`, then `resultHint`; never from Content-Type. Port of the web file.
- **Result kind** (MA13): the descriptor's `ResultKind` (`image|gif|video|audio|pdf|archive|transcript|captions|metadata|summary|hls|dash|unknown`); it picks the viewer.
- **Viewer** (MA13): a component in `src/results/viewers/` chosen by `viewerFor(kind)`; unregistered or not-yet-built kinds render `UnknownViewer`. Image/gif/pdf/archive download into `cache/results/<jobId>/`; video/audio stream `GET /result/:id` with owner headers when the API sniffed a MIME.
- **Compare** (MA13): image-only wipe/toggle of the result against the original copy kept in `cache/originals/<jobId>/`; wipe values are logical percentages (0 = start edge).
- **Job engine** (MA12): `src/jobs/jobEngine.ts`, plain TypeScript over an injected `JobTransport`; one upload at a time, SSE for the watched job (fallback 2 s poll after an error or 60 s silence), 5 s poll for the rest, nothing while backgrounded. `runtime.ts` wires the real store/native modules; `useJob(id)` watches while a screen is mounted.
- **History entry** (MA15): one row of `GET /account/history` (`HistoryEntry`, `src/api/schemas/history.ts`); the server's record of a job, listed 50 per page (offset paging, infinite query). `deadlineOf` = `deletesOn || resultExpiresAt`.
- **Pending row** (MA15): a local `jobs` record (uploading / in flight / `upload_failed`) the server history does not list yet; shown under "In progress" until a loaded page contains its `jobId`, then the server row wins.
- **Keep longer** (MA15): `PATCH /jobs/:id/retention {keepForHours}` pins a result past the account window (1 week to 1 year in the UI); needs a ledger row (`retainedObjectId`); 409 `nothing_to_keep` means it is already gone. No analytics event.
- **Entry cache** (MA15): in-memory map of the History row last opened, so the result screen can open a job the server's job map has forgotten.
- **Saved voice** (MA34): a voice kept in the account (`SavedVoice`, `src/api/schemas/voices.ts`): **cloned** from a **reference recording** or **designed** from a description; listed by `GET /voices`, capped by the plan (`limits.voicesSaved`, -1 unlimited, 0 none). Not a registry tool: the four Voices tools make, change and use them.
- **Reference recording** (MA34): the 5-60 s sample a clone is made from, recorded in the app (`expo-audio`, AAC `.m4a`, 44.1 kHz mono 128 kbps, `src/voices/recorderOptions.ts`) or picked as a file; an `IntakeFile` with `source: 'recorder'`. Auto-stops at 60 s and when the app leaves the foreground; never recorded in the background.
- **Consent record** (MA34): the ticked box "This is my voice, or I have the explicit permission of the person whose voice this is." (synced web string `voiceTools.consent.label`, legal text, never paraphrased) plus `consent=true` and `consentTextVersion=2026-10-28` (`VOICE_CONSENT_TEXT_VERSION`, `src/tools/voices/consent.ts`) on `POST /voices`; the server stores the time and its own version. Change the version only with the web constant, the server's `VOICES_CONSENT_TEXT_VERSION` and Terms 8.11 in every locale. The box resets when the recording changes.
- **Voices tools** (MA34): registry family `voices` (Tools-tab section "Voices"): `voice-clone`, `voice-design`, `voice-change` (**convert**, AI, `ai_ops`), `voice-shift` (**shift**, rubberband, `ops`). Each row has a `capability` gate over `GET /voices/capabilities` (`src/voices/gating.ts`): all hidden while the call is loading or failed; shift shows whenever it succeeded; clone and design need `enabled` and `voicesSaved != 0`; change needs `enabled` and `voicesConvert`.
- **Convert / shift / speak** (MA34): voice jobs started by the `voiceConvert`, `voiceShift` and `voiceSpeak` job starters (`src/jobs/starters/voices.ts`, the MA50 seam); the 202 `{jobId}` then flows through MA12 to the MA13 audio viewer. A convert / shift keeps its recording (`cache/originals/<jobId>/`) for the result's **A/B toggle** (Original / Result, keeps the playback position).

## Layout

`app/` Expo Router routes ((auth), (app)/(tabs)); `src/ui` tokens and base components; `src/state` Redux store, MMKV persistence, slices; `src/lib` ids, user agent, locale, Firebase availability; `src/api` baseQuery, errors, Zod schemas, `mmApi` endpoints; `src/analytics` catalog mirror, client, outbox, lifecycle, `client_error`, Crashlytics (MA07); `src/tools` registry, search, recents (MA10); `src/files` intake, pre-flight, share-into, FileArea (MA11); `src/jobs` upload transport, SSE parser, job engine, restore (MA12), `starters/` (MA50); `src/photo` Aperture: synced model/math/fixtures, Skia renderer (`skia/`, MA51 `pipeline.ts`), store, session, drafts, sheets (`ui/`) (MA50), canvas tools (`tools/`), presets, history (MA51); `src/studio` Darkroom: synced EDL model, editing math and web suites (top level, `captions/`, `fixtures/`), app code in `mobile/` (store, edits, session, drafts, assets, backend seam) (MA61), the preview's decode path `mobile/player/` and compositor `mobile/skia/compositor/` (MA62); `compositor/` + `parity/` are synced web test references.

## Ids

Android package and iOS bundle id are both `com.mediamanipulator.app`; the `development` and `preview` variants append `.dev` / `.preview` (`com.mediamanipulator.app.dev`, `com.mediamanipulator.app.preview`). Slug `media-manipulator`, scheme `mediamanipulator`. Both are single constants (`ANDROID_PACKAGE`, `IOS_BUNDLE_ID`) in `app.config.ts`.

- **Save to Photos** (MA14): image/gif/video results go to the gallery via `expo-media-library` (add-only permission asked at the first save; Android album "Media Manipulator"). Denied: a sheet offers Open settings or Save to Files instead.
- **Save to Files** (MA14): everything else. Android picks a Storage Access Framework folder once (`settings.lastSaveDirUri`) and writes into it; iOS opens the share sheet. Pure logic in `src/files/save.ts`, native bindings in `src/files/saveDeps.ts`.
- **Share link** (MM32, MA14): "Copy share link" mints a public expiring `/r/<token>` URL (`POST /jobs/:id/share`, 5 live per job, revoke all with `DELETE`); only the URL is copied, never the file name. Distinct from the **share sheet** (shares the file itself).
- **Notice** (MA14): the app's toast: `showNotice(text, tone)` in `src/ui/notice.ts`, rendered by `NoticeHost` in the signed-in layout.
- **Allowance** (MA16): one metered daily balance (`ops` or `ai_ops`) as `src/quota/useAllowance.ts` merges it: the `/account/me` snapshot, overlaid by the `quota` slice entry when its `observedAt` is newer. `-1`/`<= 0` limits are unlimited (operator).
- **Limit sheet** (MA16): `src/quota/LimitSheets.tsx`, one bottom sheet with a variant per refusal (429 quota, 429 rate limit, 403 output height, 413 size / too long / deployment cap). Neutral facts only: no price, purchase button or link (ADR MA-0008). The `footerExtra` slot is empty until MA42 / MA46. The **Plan & limits sheet** (`PlanSheet.tsx`) is the Free/Premium/Pro comparison from `/api/tiers`.
- **Tier fact** (MA16): `higherTierFact()` in `src/quota/tierFacts.ts`, a pure "Premium and Pro accept files up to 5 GB" row, or null when no higher plan raises the limit.
- **Start pre-flight** (MA16): `beforeUpload` (`src/quota/quotaGuard.ts`) refuses locally with a `quota_exceeded` `MmError` (`details.local`) when the known allowance is 0, so no doomed upload starts.
- **Audio range editor** (MA19): `src/tools/native/AudioRangeEditor.tsx`, an `expo-audio` player (100 ms status updates) under a shared `RangeTrack` (two handles + window, always left-to-right) over a placeholder bar strip; "Play selection" seeks to the start handle and pauses at the end handle. Pure math in `rangeMath.ts`.
- **Effect chips** (MA19): the multi-select chips of `audio-effects` (speed, pitch, normalize, volume, equalizer, reverb). Only chosen effects reach the options JSON (unchosen speed/volume stay 1); no chip disables Start via the registry `canRun`.

- **Trim scrubber** (MA18): `src/tools/native/TrimRangeScrubber.tsx`, an expo-video preview plus a thumbnail strip and a **Range track**; used by video-trim and video-to-gif (`FramePicker` is the single-playhead variant).
- **Range track** (MA18): `src/tools/native/RangeTrack.tsx`, two handles and a draggable window over a time axis; pure math in `rangeMath.ts`; always laid out left to right.
- **Face picker** (MA20): `src/tools/native/FacePicker.tsx`, the tap-to-choose overlay over the detected faces of `blur-faces`; boxes are normalized to the oriented image and drawn on a `contain`-fitted preview (letterbox math in `overlayMath.ts`), each with a 44 pt hit area.
- **Face detection session** (MA20): the server-side result of `POST /ai/faces/detect` (`fd_<uuid>`, 30 min TTL, bound to the SHA-256 of the exact bytes). The form keeps it as `FaceDetectionState` with the cached file URI; if it has expired at Run (or belongs to another file) `prepare` detects again from the same cached file before upload.
- **Object boxes** (MA20): the normalized rectangles drawn by `RectDrawer` for `remove-object` (`removeObjectMask.rectangles`, 4 decimals, at least one, at most 10); one pan gesture draws, moves or resizes.
- **Transcript viewer** (MA20): `TranscriptViewer` (kind `transcript`, and `captions` from a `transcribe` job) reads `GET /transcript/:id` so every export format works whatever was chosen; `CaptionsViewer` is the fallback that downloads and parses a bare `.srt`/`.vtt`. Both render `TranscriptPanel` (search, copy all, export as SRT/VTT/TXT/JSON through the share sheet, and the polled AI summary card). Tapping a cue does not seek.
- **Metadata inspector** (MA21): `src/metadata/ui/MetadataInspector.tsx`, the native categorized view of a `MetadataDocument` (summary, privacy chips, search, collapsible category sections, GPS card). Pure logic is ported from the web `lib/metadata/` into `src/metadata/` (no tag descriptions in v1). The GPS card makes no network call; "Open in maps" opens only on tap.
- **Result line** (MA21): `MetadataResultLine`, "Metadata: N kept · M removed · Compare" under a strip/edit result; Compare opens `MetadataDiffSheet` (unified diff from `GET /api/job/:id/metadata/diff`).
- **Custom metadata = strip then write** (MA21): `edit-metadata` sends `metadataMode: custom`; the API strips every tag first and writes only the fields given, so an empty form strips.
- **Managed on the web** (MA22): what the Plan card says for a Stripe subscriber. Plain text only; MA-0008 forbids any purchase, checkout, portal or pricing link on the Account tab.
- **Typed confirmation** (MA22): a destructive action stays disabled until the user types the exact phrase the API requires (`DELETE` for delete-all, `DELETE MY ACCOUNT` for account deletion). `TypedConfirmSheet`; the account screen has its own field.
- **Sign out everywhere** (MA22): `POST /account/sessions/revoke`, then the normal local sign-out. Other devices may stay signed in up to an hour (ID token lifetime).
- **Opt-out vs forget** (MA22): opt-out stops capture and keeps past data; "Delete my analytics data" (DSR) erases server data and rotates `visitorId`. Two separate paths.
- **Account wipe** (MA22): after a successful `DELETE /account` the app erases all MMKV (`mm-app`, `mm-analytics`) and cache files and rotates `visitorId`. The analytics outbox is cleared first (`discardQueued`).
- **Pre-prompt** (MA24): our own sheet ("Get notified when long jobs finish?") shown before the OS notification dialog, with surface `long_job` or `settings`. "Not now" or an OS denial silences the automatic one for 30 days (`pushPrePromptDismissedAt`).
- **job_updates channel** (MA24): the Android notification channel (id `job_updates`, "Job updates", importance high) created at startup by `expo-notifications`; the API puts this id on every push (`internal/push/fcm.go`).
- **Long job** (MA24): a job still `pending|processing` 20 s after the server accepted it. The first one triggers the pre-prompt; a push is how the user learns it finished after leaving the app.

- **Channel** (MA25): the EAS Update channel a build listens on; equals the build profile (`development`, `preview`, `production`). `eas update --channel <c>` publishes to it.
- **Runtime fingerprint** (MA25): `runtimeVersion: { policy: 'fingerprint' }`; a hash of the native project. An OTA only reaches binaries with the same fingerprint, so a native change always needs a store build.
- **Internal track** (MA25): Google Play's internal testing track; `eas submit --profile production` uploads a draft release there (promotion is MA28).
- **Remote version** (MA25): `versionCode`/`buildNumber` are owned by EAS (`appVersionSource: remote`, `autoIncrement`); the semver lives in `package.json` + `APP_VERSION` (`scripts/bump-version.mjs`).
- **Aperture assets** (MA25): every icon/splash/store PNG is rendered by `scripts/gen-icons.mjs` from the vector path data in `scripts/aperture.mjs`; `--check` (a gate) fails when a committed PNG differs from a fresh render.

- **Aperture** (MA50): the photo editor (code name `photo`, web `/photo/*`, API `/api/photo/*`). Registry row `aperture` (endpoint `photoProject`): the launcher hands the picked/shared file to `/photo/new` in memory (`src/photo/openRequest.ts`); `/photo/<projectId>` opens a saved project. The brand string is only in `photo.title` / `ApertureLauncher`.
- **PhotoDoc** (MA50): the shared non-destructive document (`src/photo/photoTypes.ts`, a generated copy of the web's Zod model). Canonical JSON = compact, sorted keys, defaults filled; the server is the sanitizer. Edits go through `mutate(store, label, fn)` on the editor's own store (`src/photo/photoStore.ts`, undo cap 100, one undo step per slider drag); drafts in MMKV `photoDraft:<projectId>`.
- **Photo canvas** (MA50): `src/photo/skia/PhotoCanvas.tsx`, the Skia preview: source image -> one SkSL runtime shader per rung-1 layer (`shaders/adjust.ts`, a line-for-line port of the web GLSL), recorded into a picture held in a reanimated shared value (no React render per slider tick). Local decode up to 24 MP (downscaled to an 8 MP texture); above that, or when Skia cannot decode, the server proxy. Skia applies EXIF orientation at decode.
- **Mask** (MA51): which pixels a layer applies to, in the geometry-corrected space (0..1 normalized): components (gradient, radial, brush PNG ≤ 1024 px / 512 KB, luminosity, colour range ≤ 8 targets, AI subject `masks/<id>.png`) folded add / subtract / intersect, feathered, inverted, scaled. Inline on the layer or named in `doc.masks` (`layer.mask = {ref}`). Rendered by `src/photo/skia/pipeline.ts` (cached per mask + geometry + source); touch tools in `src/photo/tools/`. Since MA60 (react-native-skia 3) the pipeline's `render` / `readPixels` are async, because Skia 3 readback is a promise.
- **Heal base** (MA51): the server image a heal produced (`bases/<hash>.png`, proxy `bases/<hash>.proxy.jpg`); `doc.heals[]` = `{id, maskRef?, baseRef?}`, the latest `baseRef` is the canvas source. The heal mask is posted at exactly the current base's size (the API checks it), one `ai_ops` per press.
- **Preset group** (MA51): a look appended as layers sharing `layer.group` = "Preset: <name>" (web `appendPreset`); undo removes it in one step. User presets live on the account since MA53 (see **Account preset**).
- **Account preset** (MA53): a user preset stored on the account (MM103 `photo_presets`: name, category, layers, revision, optional 96 px thumbnail), shared with the web; `src/photo/presetsApi.ts` (RTK Query, tag `PhotoPresets`, list kept 1 h; rename with `If-Match`; 403 `photo_presets_limit` → the MA16 limit sheet's neutral cap line). Saved stacks drop masks and group headers; applying re-prefixes ids `preset-<id>-n`. MA51's MMKV `photoPresets` is only a migration source (`src/photo/presets/migration.ts`): first sheet open with an empty account offers to move them (up to the cap, MMKV cleared per upload); "not now" sets `photoPresetsMigrationDeclined`; otherwise each device preset has its own Upload. No offline queue: "You're offline; try again".
- **Fixture sync** (MA50): `scripts/sync-photo-fixtures.mjs` copies the web's model, reference math (`colorMath.ts`), fixtures, goldens and built-in presets into `src/photo/` (generated header, `SOURCE.json`); `--check` is a gate. Never edit the copies; change the web and re-sync (`npm run photo:sync`). Parity: jest renders every golden with the copied CPU reference (byte-exact) and every rung-1 golden through the SkSL on CanvasKit (design §3.3 tolerances).
- **Job starter** (MA50, the MA29 seam): `StartInput.starter` names a registered `JobStarter` that creates the server job with a JSON request instead of a file upload (transport `starter`: no `upload_*` events, the engine never releases or moves the source file). `photoExport` posts `POST /photo/projects/:id/export`; tracking, restore, result and save are MA12–MA14 unchanged.
- **Tool capability** (MA50): `ToolDefinition.capability`; `src/tools/availability.ts` hides a row when the server says it cannot run it (`photo`: `GET /photo/capabilities` `enabled`/`render` false).
- **Preset row** (MA52): an Image registry row that is a front door to Aperture for one web MM100 page (`aperture-*`, `src/photo/entryRows.ts`): own title, `analyticsSlug` = the page slug (the editor's `context.tool_slug`), `defaults {panel, preset?}` passed on the open request so the editor opens on that sheet (and applies that built-in look once). Not the MA10 `presets[]` field (a folded web variant of one form).
- **Edit again** (MA52): the result-screen action for an Aperture export opened from History: reopens the export's project (`options.projectId` of the `photo_export` job) when `GET /photo/projects/:id` is 200; hidden on 404, for stateless exports, and once the server forgot the job (24 h). History's **Projects** segment lists every saved project.

- **Medi** (MA54): the AI guide (code name `assistant`, web `/api/assistant/*`, brand string only in `src/assistant/brand.ts` and `{{brand}}` copy). On the phone: `MediSheet`, a full-height `Sheet` mounted once by `MediHost` in `app/(app)/_layout.tsx`, opened through `openMedi(entry, prefill?)` (`src/assistant/mediUi.ts`) from the Tools-tab `BrandBar` button (`entry: button`) or the "Not sure? Ask Medi" row under a search with no hits (`entry: empty_search`, search text prefilled). The button and row appear only when `GET /assistant/capabilities` says `enabled` and `guide.enabled`. Guide only; the Aperture copilot is MA55.
- **Chat stream** (MA54): `POST /assistant/chat` over `expo/fetch` (`src/assistant/chatStream.ts`), parsed by the job SSE parser (`createSseParser`) and the Zod schemas in `src/api/schemas/assistant.ts`. One retry on a network drop before the first byte; aborted on Stop, sheet close and unmount; nothing is delivered after an abort. Pre-stream refusals (401/404/429/503) arrive as a synthetic `error` event with the API's code.
- **Medi action** (MA54): an `action` event's button. `open_tool {slug, preset?}` / `confirm_job {tool}` resolve the web slug through the registry (`findToolBySlug`: a row's `analyticsSlug`, or a preset's id/`analyticsSlug`) to `/(app)/tool/<family>/<toolId>?from=medi&preset=<id>`; a slug the phone lacks (Darkroom, Motion, voices, transcoding...) becomes an "Open on the web" button (in-app browser, locale-prefixed site URL); `navigate` to `/account*`, `/delete-account`, `/tools` opens the matching app screen, other site pages the web. MM116a `options` prefill is not carried (the phone's forms have no URL codec). Answer links are sanitised the same way (`safeSitePath`): only the site's own paths survive, everything else renders as plain text.

- **Darkroom** (MA-M11, ADR MA-0012): the video editor (code name `studio`, web `/studio/*` editor, API `/api/studio/*`); the brand is user-facing, every identifier, route, table and analytics name stays `studio`. Phase 1 ("Darkroom Cut", MA59–MA65) edits on the phone; render, ingest, proxies, captions and export stay on the server.
- **EDL** (MA61): the shared Darkroom document, `StudioProject` schema v3 (`src/studio/studioTypes.ts`, a synced copy of the web's Zod model; ADR ws/0004). Loaded through the copied `normalizeProject` (v1→v3, additive); the phone round-trips every field it cannot edit yet (`roundTrip.test.ts` pins it). `revision` is the server's compare-and-set token, never part of undo.
- **Studio sync** (MA61): `scripts/sync-studio.mjs` copies the EDL model and the DOM-free `lib/studio/*` editing math (plus their vitest suites, caption catalog and ASS goldens) from UI `main` into `src/studio/` with a generated header and `SOURCE.json`; `--check` is a gate (`npm run studio:sync` to refresh). The file set comes from a transitive import scan; web-only files are listed in the script's `EXCLUDED`. Two web imports are rewritten to app seams: `studioBackend` / `translator/mode` -> `src/studio/mobile/backend.ts` (URL builders only), `draftStore` -> `src/studio/mobile/drafts.ts`; the studio colour math / LUT parser resolve to Aperture's copies in `src/photo/`. The copied suites run under jest through `src/studio/mobile/vitestShim.ts` (jest maps `vitest`). Never edit a copy.
- **Studio store** (MA61): `src/studio/mobile/studioStore.ts`, the editor's own Redux store (like `photoStore`): `mutate(store, label, fn)` with `fn` one of the `edits.ts` recipes over the copied ops; `beginGesture`/`endGesture` = one undo step per drag; snapshot undo capped at 50; a locked-track edit is dropped whole (`lockNotice`). Selection and playhead stay out of history.
- **Studio session** (MA61): `session.ts`: open (GET -> store -> draft decision by the copied `evaluateDraft`), autosave PUT 1.2 s after the last edit with `expectedRevision`, retries by the copied `saveState` machine; 409 `revision_conflict {currentRevision, updatedAt}` blocks autosave until the conflict sheet answers Keep mine (re-send with `currentRevision`) or Load theirs (reload, no history). Drafts: MMKV `studioDraft:<projectId>` every 3 s, a `Paths.document/studio-drafts/` file above 2 MB.
- **Studio media cache** (MA61): `assets.ts` / `assetsRuntime.ts`: proxy, reversed proxy, sprite and peaks fetched with the owner headers into `cache/studio/<assetId>/`, LRU capped at 256 MB. Uploads: pre-flight (studio extensions, tier `maxFileBytes`/`maxVideoSeconds`, Wi-Fi-only above 500 MB = `settings.studioWifiOnlyLargeUploads`) -> presign -> S3 PUT via the MA12 upload task -> complete -> poll the asset list until `s3KeyProxy` exists.
- **Projects segment** (MA52, generalised by MA58): `src/projects/ProjectsList.tsx`, History's list of Aperture (`GET /photo/projects`), Darkroom (`GET /studio/projects`) and Motion (`GET /vector/projects`) projects merged newest first (`src/projects/merge.ts`). Errors are per source (one failing source shows its own line, the others still list).
- **Projects filter** (MA58): the chip row All · Aperture · Darkroom · Motion; remembered in MMKV `projectsFilter` (`src/projects/filterPref.ts`), default All; `projects_filter_changed {filter}`. Swipe-to-delete is Aperture-only; Darkroom/Motion rows have a "…" actions sheet.
- **Darkroom row thumbnail** (MA58): tile 0 of the first video clip's filmstrip sprite (`GET /studio/assets/:id/sprite`, 60 tiles × 160 px in one row; a capability URL, no auth), else a film icon. Motion rows show the Motion icon: `thumbnailKey` is a private S3 key the API serves no URL for.
- **Open on the web** (MA58): Motion opens its editor `https://www.media-manipulator.com/motion/<id>` (never locale-prefixed, like the web's own link); Darkroom has no per-project web URL, so it opens the localized Darkroom page (`/<prefix>/tools/content-studio`), where the project is in the recents list.
- **Output table** (MA58): the answer of `GET /studio/export-options` (`{table, required, caller}`, the API's MM118 table). The export sheet (`src/studio/mobile/ui/export/`) is built from it alone; the app keeps no copy. Pure rules in `exportModel.ts` (port of the web's `studioOutputs.ts` / `exportOptions.ts`). Locked entries stay listed, greyed, with "Not on your plan".
- **Video slot** (MA62): one of the preview's ≤ 4 `createVideoPlayer()` decoders (`src/studio/mobile/player/VideoPool.ts`), role `active | preroll | retained | free`. Pre-roll = the next clip per track loaded 2 s ahead; released outside ±10 s; failed after 3 s without a frame (0.22.0 has no error event). **Frame-stepped**: a speed != 1 / freeze / not-yet-reversed clip's player stays paused and is seeked per project frame, muted (no player rate in 0.22.0). **Frame pump**: `framePump.ts`, the per-frame body of the UI-runtime `useFrameCallback` (allocation-free; landing re-seek, 250 ms scrub wait); the JS side (`PreviewDriver`, 100 ms timer: pool, audio-led `Clock`, seek-only drift with a 2-frame dead band, `AudioVolumes`) talks to it only through numeric `SlotControl` / `ClockControl` objects.
- **Compositor chain** (MA62): `src/studio/mobile/skia/compositor/`, the SkSL port of the web's `glCompositor.ts`: one runtime effect per stage (geometry = crop/fit/transform, eq, lumetri, lut atlas, chromakey, alpha), one `LayerChain` per clip built once, a stage remade only when its packed uniforms change, replaced shaders retired 3 frames before `dispose()`. Blend: Skia `BlendMode` for 7 modes, a backdrop-initialised layer for `addition`. Its parity suite compares with the web's CPU reference and the web compositor's own recorded draws (`src/studio/compositor/` and `src/studio/parity/`, synced test references, never imported by app code).
- **StudioPreview** (MA62 S4): `src/studio/mobile/skia/StudioPreview.tsx`, the Darkroom preview component (`store`, `media`, `controller`): a letterboxed Skia canvas showing ONE offscreen surface's image, redrawn by a numeric shared-value toggle. UI runtime per frame: `previewFrame.ts` (pump, GPU sink, compositor; draws only when something changed). JS: `previewController.ts` (S1 driver 100 ms, fps / safe mode / perf 1 s; the scene shared value is written on change only). `useStudioPreviewController()` = `play / pause / seek / isPlaying / setSafeMode`. Dev-only screen `/dev/darkroom-preview` (redirects unless `__DEV__`).
- **Title raster** (MA62 S3): `skia/text/titleRaster.ts`, the Skia Paragraph port of the web's `rasterTitle` over the copied layout code; `titleRasters.ts` caches one image per title clip near the playhead, keyed by the web's `titleRasterKey` + fonts version. **Studio fonts**: `assets/fonts/studio/` (TTF, OFL; manifest + licence routes from `scripts/import-studio-fonts.py`), loaded as JS assets; DejaVu Sans downloaded from the web on first use.
- **Caption preview** (MA62 S4): approximate, never libass; `skia/text/captionLayout.ts` (timing / grouping pinned to the copied `.ass` goldens), drawn per look by `captionDraw.ts`, recorded as time segments once per caption edit (`captionTimeline.ts`); chip "Approximate preview".
- **Safe mode** (MA62 S4): `skia/safeMode.ts`: GPU unavailable, < 15 fps for 5 s playing, or the toggle; one video slot (the top-most visible clip at the playhead), effects off, titles on; chip "Simplified preview"; `studio_safe_mode_entered {reason}`.
- **studioExport starter** (MA58): `src/jobs/starters/studioExport.ts`, the MA50 seam for a Darkroom render: `POST /studio/projects/:id/export` (sheet body) or `POST …/exports/:exportId/again`; 200 `{jobId}`, then MA12–MA14 unchanged. The record's `toolId` is `darkroom` (no registry row); the result's task comes from the job's `options.mode` `studio_export` (`jobTaskHint`), its file name from `originalFile.name`. Long, unwatched renders are pushed by the API ("Your Darkroom export is ready"), never emailed.
